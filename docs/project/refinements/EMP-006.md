## 1. Cel

Dostarczyć bezpieczną i wymienną warstwę ustalania adresu klienta oraz kraju IP, która może zostać użyta przez przyszły endpoint wykorzystania kuponu bez zaufania do nagłówków przesłanych bezpośrednio przez klienta, bez wykonywania publicznych requestów w testach i bez utrwalania surowego adresu IP.

EMP-006 jest prerequisite dla EMP-004. Nie implementuje jeszcze wykorzystania kuponu ani decyzji `COUNTRY_NOT_ALLOWED`.

## 2. Wynik docelowy

Po zakończeniu implementacji EMP-006:

- aplikacja rozpoznaje literalny IPv4 lub IPv6 klienta;
- domyślnie ignoruje `Forwarded` i `X-Forwarded-For`;
- nagłówki proxy są honorowane tylko wtedy, gdy bezpośredni peer należy do jawnie skonfigurowanej listy zaufanych CIDR;
- łańcuch proxy jest analizowany od prawej do lewej, a klientem jest pierwszy hop spoza zaufanej infrastruktury;
- błędne, niejednoznaczne lub zbyt długie nagłówki kończą się fail-closed;
- zewnętrzny dostawca GeoIP jest ukryty za portem;
- domyślny adapter demonstracyjny korzysta wyłącznie z HTTPS i pobiera tylko `success`, `country_code` oraz `message`;
- timeout, HTTP 429/5xx, błąd transportu, błędny JSON i odpowiedź `success=false` nie są interpretowane jako zły kraj;
- lokalne i testowe środowisko używa jawnego stubu bez publicznego bypassu HTTP;
- surowy adres IP nie jest utrwalany ani logowany;
- testy są deterministyczne i nie zależą od publicznego Internetu.

## 5. Granice i porty

```java
public interface ClientIpResolver {
    ClientIpAddress resolve(HttpServletRequest request);
}

public interface GeoLocationResolver {
    CountryCode resolve(ClientIpAddress clientIpAddress);
}
```

`ClientIpResolver` odpowiada wyłącznie za wiarygodne ustalenie adresu. `GeoLocationResolver` odpowiada wyłącznie za mapowanie publicznego adresu na `CountryCode`. Żaden port nie zna kuponu ani reguły redemption.

Publiczne kontrakty otrzymują znaczący Javadoc opisujący zaufanie, failure modes i brak DNS. Lokalne zmienne oraz oczywiste prywatne metody nie wymagają mechanicznych komentarzy.

## 6. Kontrakt konfiguracji

Planowane właściwości:

```yaml
coupon:
  client-ip:
    mode: direct
    trusted-proxies: []
    max-forwarded-hops: 20
    max-header-length: 4096
  geolocation:
    mode: http
    base-url: https://ipwho.is
    connect-timeout: 500ms
    response-timeout: 1s
```

Profile `local` i `test` mogą ustawić:

```yaml
coupon:
  geolocation:
    mode: stub
    stub-country: PL
```

Reguły uruchomienia:

- `direct` jest bezpiecznym ustawieniem domyślnym;
- `trusted-proxy` wymaga co najmniej jednego poprawnego CIDR i powoduje startup failure przy błędnej konfiguracji;
- `stub` jest dostępny wyłącznie w profilach `local` lub `test`;
- uruchomienie stubu poza tymi profilami kończy startup failure;
- `base-url` dla adaptera HTTP musi używać `https`;
- timeouty muszą być dodatnie i mieć bezpieczne maksimum konfiguracyjne;
- żaden sekret ani klucz API nie jest wymagany przez darmowy adapter demonstracyjny.

## 7. Algorytm ustalania Client IP

### 7.1. Tryb `direct`

1. Pobierz `request.getRemoteAddr()`.
2. Parsuj wyłącznie literalny IPv4 lub IPv6.
3. Nie wykonuj DNS.
4. Ignoruj wszystkie nagłówki `Forwarded` i `X-Forwarded-For`, nawet jeśli klient je przesłał.
5. Błędny remote address powoduje wewnętrzny `ClientIpResolutionException`.

### 7.2. Tryb `trusted-proxy`

1. Parsuj immediate peer z `request.getRemoteAddr()`.
2. Jeżeli immediate peer nie należy do `trusted-proxies`, zignoruj nagłówki i użyj immediate peer.
3. Jeżeli peer jest zaufany, użyj `Forwarded`, jeśli istnieje; `X-Forwarded-For` jest fallbackiem tylko przy braku `Forwarded`.
4. Nie przełączaj się na `X-Forwarded-For`, gdy obecny `Forwarded` jest błędny — taki request kończy się fail-closed.
5. Zbuduj uporządkowany łańcuch adresów z nagłówka, a następnie dodaj immediate peer jako ostatni hop.
6. Idź od prawej do lewej i pomijaj adresy należące do `trusted-proxies`.
7. Pierwszy adres spoza zaufanych CIDR jest adresem klienta.
8. Jeżeli nie istnieje żaden niezaufany hop, resolution kończy się błędem zamiast wybierać dowolny adres.

Przed wyborem nagłówka adapter pobiera wszystkie fizyczne wartości przez odpowiednik `request.getHeaders("Forwarded")` i `request.getHeaders("X-Forwarded-For")`. Więcej niż jedna fizyczna wartość `Forwarded` albo więcej niż jedna fizyczna wartość `X-Forwarded-For` powoduje fail-closed; aplikacja nie scala niejawnie field-lines. Pojedynczy `Forwarded` lub pojedynczy XFF może zawierać rozdzielony przecinkami łańcuch hopów. Gdy oba pojedyncze nagłówki istnieją, wynik pochodzi wyłącznie z `Forwarded`; błędny `Forwarded` nadal nie fallbackuje do XFF. Kontrakt nie twierdzi, że aplikacja odzyska field-lines, które konkretny kontener servletowy połączył wcześniej; integracyjne testy potwierdzą zachowanie używanego Spring/Tomcat.

Warunkiem operacyjnym jest to, że boundary proxy usuwa nagłówki forwarded pochodzące od klienta i zapisuje własny, kanoniczny łańcuch. Sama aplikacja nie może kryptograficznie potwierdzić autora nagłówka.

### 7.3. Dopuszczalna składnia

- IPv4, np. `203.0.113.10`;
- `Forwarded` wspiera wyłącznie IPv4 bez portu (`for=203.0.113.10`), bracketed IPv6 bez portu (`for="[2001:db8::1]"`) oraz bracketed IPv6 z portem (`for="[2001:db8::1]:4711"`); port 1–65535 jest walidowany i usuwany przed parsowaniem literału IPv6;
- `X-Forwarded-For` wspiera wyłącznie literały IPv4 albo IPv6 bez portów; bracketed forma, IPv4 z portem i IPv6 z portem są odrzucane;
- `request.getRemoteAddr()` wspiera wyłącznie literalny adres bez portu;
- odrzucane są niebracketowany IPv6 z portem, IPv4 z portem, pusty port, port poza zakresem 1–65535 i dodatkowy tekst po porcie;
- `unknown`, identyfikatory obfuscated zaczynające się `_`, hostnames, zone identifiers i puste elementy są niedozwolone;
- wszystkie wartości muszą przejść ścisły parser literalnego adresu;
- łączna długość używanego nagłówka nie może przekroczyć `max-header-length`;
- liczba elementów nie może przekroczyć `max-forwarded-hops`.

To jest bezpieczny podzbiór RFC 7239 wymagany przez projekt, nie implementacja całego RFC.

### 7.4. Kontrakt boundary proxy

W trybie `trusted-proxy` infrastruktura wdrożeniowa MUSI usunąć wszystkie instancje `Forwarded` i `X-Forwarded-For` przychodzące od klienta, wygenerować jeden kanoniczny nagłówek zgodny z tym kontraktem i nie przekazywać równoległych, konfliktowych field-lines. Port aplikacji nie może być dostępny publicznie z pominięciem tego proxy, a immediate peer proxy musi należeć do skonfigurowanego trusted CIDR. Jest to obowiązek deploymentu, nie deklaracji klienta. Aplikacja nadal weryfikuje immediate peer i failuje dla niejednoznacznych nagłówków; przy braku poprawnej konfiguracji proxy używany jest tryb `direct`, nigdy automatyczne zaufanie do headerów.

## 8. Polityka adresów publicznych

Publiczny adapter GeoIP nie jest wywoływany dla adresów, które nie są globalnie osiągalnym unicastem. Polityka obejmuje co najmniej:

- unspecified;
- loopback;
- link-local;
- private/site-local;
- multicast;
- documentation/test networks;
- benchmark, discard-only i inne bloki specjalnego przeznaczenia wskazane przez rejestry IANA;
- IPv4-mapped IPv6 po bezpiecznej normalizacji.

Takie adresy powodują `GeolocationUnavailableException`. W profilach `local` i `test` stub może obsłużyć adres prywatny, ponieważ nie wysyła go na zewnątrz.

## 9. Kontrakt adaptera GeoIP

Domyślna demonstracyjna konfiguracja:

```text
GET https://ipwho.is/{encoded-ip}?fields=success,country_code,message
Accept: application/json
```

Reguły:

- URI powstaje z wcześniej sparsowanego adresu, nie z dowolnego tekstu requestu;
- adapter odczytuje wyłącznie `success`, `country_code` i `message`;
- `country_code` musi przejść istniejący `CountryCode`;
- HTTP 2xx z `success=true` i poprawnym krajem oznacza sukces;
- `success=false`, brak pola, błędny kraj lub błędny JSON oznaczają niedostępność geolokalizacji;
- HTTP 429, 5xx, timeout, DNS/TLS/connection error oznaczają niedostępność geolokalizacji;
- brak automatycznego retry w ścieżce requestu;
- automatyczne redirecty są wyłączone; każda odpowiedź 300–399 powoduje `GeolocationUnavailableException`, a adapter nie wykonuje requestu pod `Location`, także do tego samego hosta;
- adapter żąda `Accept: application/json` i może żądać `Accept-Encoding: identity`;
- limit body wynosi 16 KiB = 16 384 bajty: poprawny `Content-Length` większy niż 16 384 jest odrzucany przed pełnym odczytem, a stream bez `Content-Length` jest czytany maksymalnie do 16 385 bajtów; odczyt 16 385. bajtu przerywa przetwarzanie i daje `GeolocationUnavailableException`, natomiast dokładnie 16 384 bajty są dozwolone;
- limit dotyczy danych przekazywanych do parsera JSON, a zbyt duże body nie trafia do logu ani wyjątku;
- treść odpowiedzi dostawcy nie trafia do odpowiedzi publicznej ani logów aplikacyjnych.

Darmowy provider jest adapterem demonstracyjnym, nie deklaracją gotowości do dużej produkcji. Endpoint i implementację można wymienić bez zmiany domeny.

## 10. Failure policy

| Źródło błędu | Wyjątek wewnętrzny | Publiczny kontrakt przyszłego redemption |
|---|---|---|
| brak poprawnego remote address | `ClientIpResolutionException` | 503 `GEOLOCATION_UNAVAILABLE` |
| zbyt długi lub zbyt wieloelementowy header | `ClientIpResolutionException` | 503 `GEOLOCATION_UNAVAILABLE` |
| błędny `Forwarded` od zaufanego proxy | `ClientIpResolutionException` | 503 `GEOLOCATION_UNAVAILABLE` |
| adres niepubliczny dla adaptera HTTP | `GeolocationUnavailableException` | 503 `GEOLOCATION_UNAVAILABLE` |
| timeout / DNS / TLS / connection error | `GeolocationUnavailableException` | 503 `GEOLOCATION_UNAVAILABLE` |
| HTTP 429 lub 5xx | `GeolocationUnavailableException` | 503 `GEOLOCATION_UNAVAILABLE` |
| `success=false` lub błędny JSON | `GeolocationUnavailableException` | 503 `GEOLOCATION_UNAVAILABLE` |
| poprawny kraj, ale inny niż kupon | poza EMP-006 | 403 `COUNTRY_NOT_ALLOWED` w EMP-004 |

Błąd infrastruktury nigdy nie może zostać zmapowany na 403. EMP-006 nie dodaje jeszcze publicznego endpointu, dlatego runtime OpenAPI nadal opisuje wyłącznie create coupon.

## 11. Bezpieczeństwo i prywatność

- raw IP istnieje wyłącznie w pamięci podczas requestu;
- baza nie otrzymuje nowej kolumny IP;
- `coupon_redemptions` przechowuje później wyłącznie rozpoznany kraj;
- raw IP nie jest częścią exception message, Problem Details, structured logs ani metric labels;
- log techniczny może zawierać nazwę etapu i kategorię błędu, ale nie IP ani body dostawcy;
- nie powstaje trwały hash IP;
- wywołanie publicznego GeoIP przekazuje adres IP zewnętrznemu podmiotowi i wymaga jawnego opisu w finalnym README oraz przeglądu prywatności przed rzeczywistą produkcją;
- konfiguracja zaufanych proxy jest częścią granicy bezpieczeństwa wdrożenia;
- publiczny klient nie otrzymuje możliwości ustawienia kraju przez body lub specjalny nagłówek.

## 13. Strategia testów

### Unit

- ścisłe parsowanie IPv4 i IPv6;
- odrzucenie hostname, zone ID, `unknown` i obfuscated identifier;
- bezpośredni remote address ignoruje spoofed headers;
- niezaufany peer ignoruje forwarded headers;
- dwa fizyczne `Forwarded` albo dwa fizyczne XFF kończą się failure, a pojedynczy wielohopowy header pozostaje obsługiwany;
- konflikt `Forwarded` i XFF używa wyłącznie `Forwarded`, a błędny `Forwarded` nie fallbackuje do poprawnego XFF;
- testowane są wszystkie dopuszczone i odrzucone formy IPv6/portów oraz trusted peer z kanonicznym albo niejednoznacznym nagłówkiem;
- zaufany peer i poprawny łańcuch wybierają pierwszy niezaufany hop od prawej;
- `Forwarded` ma pierwszeństwo nad `X-Forwarded-For`;
- błędny `Forwarded` nie fallbackuje do XFF;
- limit długości i hopów;
- CIDR IPv4/IPv6;
- klasyfikacja adresów specjalnych;
- brak raw IP w message wyjątków.

### Adapter HTTP

Testy na lokalnym WireMock lub równoważnym serwerze:

- 200 + success + country;
- 200 + `success=false`;
- 200 + brak/błędny `country_code`;
- malformed JSON;
- response body ponad limit;
- 429;
- 500;
- connect timeout;
- response timeout;
- redirect;
- redirect 300–399 wykonuje dokładnie jeden request i nie śledzi `Location`;
- Content-Length = 16 385 jest odrzucany bez parsowania;
- brak Content-Length i stream 16 385 przerywa odczyt; dokładnie 16 384 bajty nie są odrzucone wyłącznie przez limit;
- zbyt duże body nie wycieka do message wyjątku;
- potwierdzenie query `fields=success,country_code,message`;
- brak retry przez dokładnie jedno wywołanie.

### Konfiguracja

- `direct` startuje bez trusted CIDR;
- `trusted-proxy` bez CIDR nie startuje;
- zły CIDR nie startuje;
- HTTP base URL nie startuje;
- stub działa w `local` i `test`;
- stub poza dozwolonym profilem nie startuje;
- brak stub country nie startuje.

### Integracja

- Spring context z fake providerem;
- żaden test nie wywołuje publicznego `ipwho.is`;
- Docker local profile dla prywatnego adresu kontenera korzysta ze stubu;
- `make verify` pozostaje powtarzalne offline po pobraniu zależności Maven.

## 16. Kryteria akceptacji implementacji

- **EMP006-AC-01:** bez zaufanego proxy nagłówki klienta nie zmieniają rozpoznanego IP;
- **EMP006-AC-02:** zaufany łańcuch wybiera pierwszy niezaufany hop od prawej dla IPv4 i IPv6;
- **EMP006-AC-03:** parser nie wykonuje DNS i odrzuca hostnames, `unknown`, obfuscated IDs oraz zone IDs;
- **EMP006-AC-04:** błędny `Forwarded` failuje bez fallbacku do XFF;

- **EMP006-AC-08:** timeout, 429, 5xx, `success=false`, invalid JSON i invalid country mapują się na wewnętrzną niedostępność;
- **EMP006-AC-09:** stub jest dostępny wyłącznie w `local`/`test`, bez publicznego bypass header;
- **EMP006-AC-10:** raw IP nie jest utrwalany, logowany ani zwracany;
- **EMP006-AC-11:** testy nie wywołują publicznego Internetu;
- **EMP006-AC-12:** publiczne kontrakty mają znaczący Javadoc, DocLint i existing gates pozostają zielone;
- **EMP006-AC-13:** canonical OpenAPI nie deklaruje jeszcze redemption;
- **EMP006-AC-14:** `make verify` i izolowany Docker smoke przechodzą;
- **EMP006-AC-15:** dokumentacja, checksums, source export, commit i push są spójne;

- **EMP006-AC-17:** więcej niż jedna fizyczna wartość `Forwarded` albo XFF powoduje fail-closed; pojedynczy wielohopowy header pozostaje obsługiwany.

2. Wspólny publiczny błąd 503 `GEOLOCATION_UNAVAILABLE` obejmuje failure Client IP i GeoIP.
3. EMP-006 nie dodaje cache, retry ani fallbacku providera.
4. Błędny `Forwarded` failuje bez fallbacku do XFF.
5. Stub kraju `PL` działa wyłącznie w profilach `local` i `test`; poza nimi startup failuje.

### Niebędące blockerem

- docelowy reverse proxy w produkcji nie jest częścią zadania;
- dokładna biblioteka HTTP stub może zostać wybrana podczas implementacji po sprawdzeniu istniejących zależności;
- metryki mogą zostać fizycznie dostarczone w EMP-010, o ile EMP-006 zachowa stabilne kategorie błędów.

## 20. Decyzja końcowa

Pierwszy review otrzymał `REJECT` dla pięciu luk bezpieczeństwa, a security amendment usunął je dokumentacyjnie. Właściciel formalnie zaakceptował pięć decyzji i ponowną rekomendację `ACCEPT`. Refinement jest zamrożony jako `ACCEPTED`; implementacja EMP-006 może rozpocząć się jako osobny checkpoint, lecz nie została jeszcze wykonana.
