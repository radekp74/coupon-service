## 1. Cel

Udostępnić testerom jednoznaczny, interaktywny i wersjonowany opis istniejącego REST API oraz wprowadzić proporcjonalną politykę Javadoc dla publicznych kontraktów Java.

## 2. Powód zmiany kolejności

`EMP-004` wymaga GeoIP i kompletnego kontraktu błędów, aby publiczny endpoint redemption nie utrwalał danych bez wiarygodnie ustalonego kraju. Zaakceptowany `EMP-001` przewidywał wykonanie `EMP-006/007` przed `EMP-004/005`. Dlatego `EMP-004` zostaje czasowo `BLOCKED`, a aktywnym zadaniem jest `EMP-007`.

## 3. Wynik

Po zakończeniu checkpointu:

- `docs/api/openapi.yaml` jest jedynym wersjonowanym źródłem prawdy publicznego REST API;
- ten sam plik jest pakowany do artefaktu aplikacji i dostępny jako `/openapi.yaml`;
- tester otwiera Swagger UI pod `/swagger-ui` i może użyć `Try it out`;
- Swagger UI nie korzysta z domyślnego Petstore ani z automatycznie generowanego opisu jako źródła kontraktu;
- publiczne kontrakty domenowe i aplikacyjne mają znaczący Javadoc;
- Maven uruchamia DocLint;
- test integracyjny potwierdza dostępność specyfikacji i UI;
- OpenAPI nadal opisuje wyłącznie endpointy rzeczywiście zaimplementowane.

## 4. Zakres

- `springdoc-openapi-starter-webmvc-ui` zgodny ze Spring Boot 3.5.16;
- Swagger UI skonfigurowany do odczytu `/openapi.yaml`;
- Maven resources kopiuje `docs/api/openapi.yaml` do classpath `static`;
- Docker build otrzymuje canonical OpenAPI bez kopiowania całego katalogu dokumentacji;
- aktualizacja create-coupon OpenAPI: finalny status EMP-003, opisy, przykłady i Problem Details;
- integracyjny test dostępności `/openapi.yaml` i Swagger UI;
- Javadoc dla publicznych kontraktów istniejącego zakresu EMP-003;
- Maven Javadoc Plugin z DocLint;
- statyczny checker `EMP-007`;
- aktualizacja governance, backlogu, statusu, changelogu, decyzji, ryzyk i dokumentacji.

## 5. Poza zakresem

## 6. Źródło prawdy OpenAPI

Canonical spec:

```text
docs/api/openapi.yaml
```

Maven kopiuje ją do:

```text
classpath:/static/openapi.yaml
```

Runtime:

```text
GET /openapi.yaml
GET /swagger-ui
```

Swagger UI ładuje `/openapi.yaml`. Springdoc może udostępniać diagnostyczny `/v3/api-docs`, lecz Swagger UI ma jawnie wskazywać `/openapi.yaml`; wyłącznie wersjonowany YAML jest kontraktem.

## 7. Wybór biblioteki

- `org.springdoc:springdoc-openapi-starter-webmvc-ui:2.9.0`;
- wersja 2.9.0 została wydana z aktualizacją do Spring Boot 3.5.16;
- biblioteka dostarcza Swagger UI, lecz nie jest źródłem semantyki kontraktu;
- usunięcie biblioteki w przyszłości nie może zmienić treści OpenAPI.

## 8. Polityka Javadoc

Javadoc jest obowiązkowy dla:

- publicznych value objects i modeli domenowych;
- publicznych use case'ów i portów;
- publicznych DTO i kontrolerów, gdy opisują kontrakt;
- wyjątków biznesowych, gdy ich znaczenie nie wynika jednoznacznie z nazwy;
- metod o ważnych skutkach ubocznych, transakcji lub wymaganiach współbieżności.

Javadoc nie ma powtarzać typów ani nazw. Komentarze implementacyjne opisują przyczynę nieoczywistej decyzji.

## 9. Bezpieczeństwo i środowiska

- Swagger UI jest dostępny lokalnie i w testach;
- finalna konfiguracja produkcyjna może go wyłączyć przez właściwość środowiskową;
- specyfikacja nie zawiera sekretów, tokenów, prywatnych adresów ani wewnętrznych nazw bazodanowych;
- `Try it out` wykonuje wyłącznie publiczne operacje opisane w specyfikacji;
- brak auth pozostaje jawnie opisanym ograniczeniem zadania;
- `/v3/api-docs` nie jest traktowane jako źródło prawdy i nie zastępuje review canonical YAML.

## 10. Failure modes

| Failure | Zachowanie |
|---|---|
| brak canonical YAML w build context | build lub checker fail |
| Swagger UI używa Petstore lub generated spec zamiast canonical YAML | test/checker fail |
| YAML opisuje niezaimplementowany endpoint | review/checker fail |
| endpoint zmienia status bez zmiany YAML | test/checker fail |
| błąd DocLint | Maven verify fail |
| UI niedostępne w profilu lokalnym/testowym | integration/runtime smoke fail |
| komentarz powtarza kod lub jest nieaktualny | review fail |
